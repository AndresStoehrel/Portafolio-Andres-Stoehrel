Estructura y flujo de datos — Portafolio Andrés Stoehrel

Archivo de revisión (no forma parte de la app). La app es un portafolio React/Vite de una sola página: Home y caso de estudio se alternan según estado en App.tsx. Los datos son mock estáticos en src/data/projects.ts.

1. Estructura del proyecto

portafolio-andres-stoehrel/ ├── index.html ← monta #root ├── package.json ← Vite + React ├── src/ │ ├── main.tsx ← createRoot → App │ ├── App.tsx ← estado, routing interno, props │ ├── index.css ← Tailwind / tokens de color │ ├── data/ │ │ └── projects.ts ← PROJECTS[] (Remitly, Telepianxos, Pedidos Ya) │ ├── assets/images/ ← capturas de prototipo (JPG) │ └── components/ │ ├── Header.tsx │ ├── HomeView.tsx ← Hero, About, Work, Contact │ ├── CaseStudyView.tsx │ ├── DeviceMockup.tsx │ └── EmptyState.tsx └── diagrama-estructura-flujo.html ← este archivo (nuevo, aparte)

2. Pantallas (vistas)

Vista A

HomeView

Una sola página con anclas: Hero, About (#about), Proyectos seleccionados (#work), Contacto (#contact).

Vista B

CaseStudyView

Reemplaza el main. Cabecera, desafío/métricas, insights, solución (antes/después + features), aprendizajes, CTA Behance y prev/next.

Siempre visible

Header

Sticky. Logo → home. About / Work / Contact hacen scroll (si hay caso abierto, primero vuelve a home).

Fallback

EmptyState

Lista vacía si isEmptyState es true, o “caso no encontrado” si el id no existe en PROJECTS.

3. Flujo de datos de ejemplo

Fuente

projects.ts → PROJECTS

  • id, number, title, oneLiner
  • metadata, heroTheme, problemStatement
  • metrics[], insights[], designGoal
  • comparison, featureHighlights[]
  • learnings[], whatToDoDifferently, behanceUrl
→
Orquestación

App.tsx

  • selectedProjectId: null = Home
  • isEmptyState: si true, activeProjects = []
  • si hay id → PROJECTS.find(id) = currentProject
  • prev/next recorren el array en círculo
Home

HomeView ← activeProjects

Mapea cada proyecto a una fila (número, título, miniatura por project.id). Click llama onSelectProject(id).

→
Estado

setSelectedProjectId(id)

Ejemplo: click en “Remitly” → id remitly. App busca ese objeto y monta CaseStudyView.

Caso

CaseStudyView ← project

Renderiza el objeto completo. DeviceMockup recibe projectId + mockupType de cada feature y elige JPGs en assets.

→
Local UI

comparisonMode

Estado interno del caso: before / after / side-by-side. No modifica PROJECTS. Prev/next cambian el id en App.

No hay API ni Gemini en el flujo de pantallas: el contenido visible sale del array mock y de las imágenes locales. El toggle de empty state está definido en App pero no está cableado al Header.
